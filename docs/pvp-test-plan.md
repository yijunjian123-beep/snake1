# PVP 全面测试计划

## 适用范围

当前 PVP 已同时覆盖本地双人烟测和在线真人对战：默认首屏显示 PVE / PVP 双入口，`?localPvp=1` 继续作为本地 PVP 烟测入口，在线 PVP 则走服务端转发输入 + 客户端确定性模拟，P2 不再依赖 scripted 占位。本计划先验证入口闭环、本地双蛇 tick、输入、碰撞、结算、渲染和性能预算，再覆盖在线同步与断线/限流专项。

在线 PVP 允许新增最小 Node.js + TypeScript WebSocket 后端、shared PVP 协议类型、shared PVP 游戏逻辑、服务端房间管理、随机匹配、权威 tick / 权威 `gameOver`、Docker 部署配置、GitHub Pages 前端部署配置和 PVP 压测脚本。仍禁止数据库、登录系统、支付、排行榜、大型后端框架、UI 组件内堆网络逻辑、硬编码生产 WebSocket 地址，以及任何破坏 PVE 或 `localPvp` 的改动。

## 测试目标

- 单人模式不能因为 PVP 改动出现回归
- 主入口、PVP 房间壳层、PVE/PVP 结算双按钮必须闭环
- 双蛇状态稳定，输入、碰撞、胜负和平局结算一致
- 双人场景下 Canvas、粒子、拖尾、黑洞和 HUD 不造成明显卡顿
- 桌面和移动端都能完成一局，不因 resize、横竖屏或 pointer events 崩坏
- 性能数据有单人基线和 PVP 对照，能判断后续优化是否有效

## 入口检查

每轮 PVP 测试先跑：

```bash
npx tsc --noEmit
npm test
npm run build
```

本地页面检查：

- 主入口和 PVE：`/`
- PVP 房间壳层：`/` 后点击 PVP
- 本地 PVP：`/?localPvp=1`
- 本地 WebSocket 配置：`VITE_PVP_WS_URL=ws://localhost:8787/ws`
- 生产 WebSocket 配置：`VITE_PVP_WS_URL=wss://your-domain/ws`

如果 Windows 环境里 `npm` 或 `node` 不在 PATH，按 `docs/architecture/05-test-strategy.md` 里的捆绑 Node 方式执行同等命令。

## 阶段 1：入口和结算闭环

- [ ] 普通打开 `/` 时先看到 PVE / PVP 双入口，不直接进入 PVP。
- [ ] 点击 PVE 能进入原单人玩法。
- [ ] 单人死亡或复活提示时显示“继续游戏 / 回到主界面”。
- [ ] PVE 的“继续游戏”沿用复活或重开逻辑。
- [ ] PVE 的“回到主界面”回到 PVE / PVP 双入口。
- [ ] 点击 PVP 进入 PVP 房间面板壳层。
- [ ] 房间面板显示创建房间、房间号、加入房间、准备、返回主界面。
- [ ] 创建/加入/准备不会伪造真实联机成功，只提示房间服务尚未接入。
- [ ] 房间面板返回主界面后，仍回到 PVE / PVP 双入口。
- [ ] 打开 `/?localPvp=1` 后仍能进入本地双人烟测。
- [ ] localPvp 结算后显示“继续游戏 / 回到主界面”。
- [ ] localPvp 的“继续游戏”重置本地 PVP 对局。
- [ ] localPvp 的“回到主界面”不会被 URL 参数立刻拉回对局。

## 阶段 2：单人基线

先记录单人模式的对照数据，后续 PVP 性能只和这份基线比。

- [ ] 单人正常开局、移动、吃星核、增长、得分
- [ ] 暂停、继续、重开、死亡和 localStorage 最高分正常
- [ ] 黑洞、星门、冲刺、粒子爆炸、震屏和背景脉冲正常
- [ ] 桌面键盘、移动端摇杆和冲刺按钮正常
- [ ] resize 后 Canvas 尺寸、网格、碰撞和 UI 正常
- [ ] 记录 3 分钟单人性能：平均 FPS、最差 FPS、平均模拟耗时、平均渲染耗时、内存趋势

## 阶段 3：PVP 功能回归

- [ ] `?localPvp=1` 能进入本地 PVP，HUD 明确显示 PVP 状态
- [ ] 两名玩家开局位置安全，不重叠，不贴墙秒死
- [ ] 两条蛇按共享 tick 前进，速度节奏不明显分裂
- [ ] P1 输入只影响 P1，P2 输入队列只影响 P2
- [ ] 两名玩家都能拾取星核并分别计分、增长
- [ ] 同一个星核被同时争抢时，只会结算给一个玩家
- [ ] 撞墙、自撞、撞黑洞、撞对手身体都会进入正确死亡状态
- [ ] 头对头碰撞能稳定结算胜负或平局
- [ ] 一名玩家死亡后，另一名玩家的状态和结算正常
- [ ] 重开后 match、world、players、inputs 都被清干净
- [ ] PVP 结算显示 P1/P2 分数、长度、胜者/败者/平局和死亡原因
- [ ] 键盘 `R` 在对局中重开当前 PVE 或 localPvp 对局，不污染下一局输入队列

## 阶段 4：PVP 压力场景

### 普通局

- 2 名玩家，正常移动和拾取星核，持续 3 分钟
- 目标：桌面平均 FPS 接近 60，连续卡顿不超过 2 次

### 高压局

- 2 条中长蛇，多黑洞，多次连续冲刺，多次粒子爆炸
- 目标：大多数帧低于 16.7ms，短时尖峰不形成连续卡顿；模拟和渲染 title 值不能长期高于 10ms

### 极限局

- 两条蛇接近当前合理长度上限，星门和黑洞同时存在，拾取和死亡反馈频繁触发
- 目标：平均帧耗时相比单人基线增长尽量控制在 20%-30% 内

### 长时间局

- PVP 连续运行 15-30 分钟
- 目标：内存不持续线性上涨，重开后不会越来越卡

### 移动端局

- 真机横屏进入 `?localPvp=1`，完成至少 3 局
- 目标：摇杆、冲刺按钮、横屏提示和 pointer events 都稳定，操作延迟不明显

## 性能观测口径

优先记录这些指标：

- 平均 FPS
- 最差 1% FPS 或明显卡顿次数
- 平均模拟耗时
- 平均渲染耗时
- 最长单帧耗时
- JS heap 起始值、峰值、结束值
- 粒子、拖尾、奖励爆散等高频对象数量
- 蛇身长度、黑洞数量、星核数量和当前质量等级

当前状态栏 title 已包含逻辑耗时和渲染耗时，可用于本地压测时快速观察；更正式的记录使用 `docs/pvp-performance-record-template.md`。

## 性能采集方法

最轻量记录：

- 打开页面后让对局稳定运行 10 秒，再开始计时。
- 每 30 秒记录一次状态栏 FPS 和状态栏 title 中的逻辑/渲染耗时。
- 每个 3 分钟场景至少记录 6 个采样点。
- 出现肉眼可见卡顿时记录时间点、当时蛇长、黑洞数量和是否正在冲刺/爆炸。

浏览器 DevTools 记录：

- Performance 面板录制 30-60 秒普通局和高压局。
- 关注 Main thread 长任务、GC、Canvas 绘制、脚本执行峰值。
- Memory 或 Performance memory 记录开始、3 分钟、10 分钟、重开后的 JS heap。
- 不把 DevTools 打开状态下的数据当成最终 FPS，只用于定位瓶颈。

移动端记录：

- 优先真机横屏，至少完成 3 局。
- 记录触控延迟、摇杆释放、冲刺按钮、横屏提示遮罩、结算按钮是否可点。
- 如果只能用桌面模拟器，必须在结论中标记“未真机验证”。

## 性能准入建议

- 必须通过：PVE 3 分钟基线、localPvp 3 分钟普通局、移动横屏布局检查。
- 建议通过：localPvp 高压局 3 分钟、连续重开 10 次、15 分钟长时间局。
- 阻塞问题：连续 3 秒以上不可控卡顿、控制输入明显丢失、重开后越来越卡、JS heap 明显线性上涨。
- 可延期优化：偶发单帧尖峰、DevTools 打开时 FPS 降低、极限长蛇下短暂粒子掉帧。

## 自动化测试补强

优先补这些回归测试：

- [ ] PVP 开局安全生成：两条蛇不重叠、不贴危险区
- [ ] 输入隔离：P1/P2 命令不会互相污染
- [ ] 同 tick 拾取冲突：同一星核只被一个玩家吃到
- [ ] 双人碰撞：墙、自撞、撞对手、头对头、黑洞
- [ ] 重开清理：旧 match、inputs、winner、死亡状态不残留
- [ ] 长蛇占用表：中长蛇移动和碰撞不退化到字符串扫描
- [ ] resize 之后：网格尺寸、蛇身坐标和碰撞仍一致
