# 本地双人 PVP 架构垫层

这一阶段只做 PVP 地基，不接真实网络房间。目标是让同一个页面先稳定跑 2 条蛇，验证 tick、输入、碰撞、结算、渲染和性能预算，后续远端 PVP 只替换输入来源。

## 当前状态

- 默认首屏是 PVE / PVP 双入口，PVE 仍走原来的单人玩法。
- PVP 正式入口目前进入房间面板壳层，创建房间、加入房间、准备都不会伪造成功状态。
- 本地双人模拟仍通过 URL 参数开启：`?localPvp=1`，只作为开发烟测入口。
- 当前 P1 使用本地键盘/触控输入，P2 使用脚本模拟输入。
- P2 只是远端玩家占位，不代表最终 AI 玩法。
- PVP 结算态统一显示“继续游戏 / 回到主界面”两个主操作。

## 本次新增

- 首屏从单一开始按钮改为 PVE / PVP 两个模式入口。
- PVP 入口接入房间面板壳层，并明确提示“房间服务尚未接入”。
- 结算态统一双按钮：
  - PVE 下“继续游戏”沿用复活或重开逻辑，“回到主界面”回到 PVE/PVP 选择。
  - localPvp 下“继续游戏”重置本地 PVP 对局，“回到主界面”离开当前 PVP 上下文。
- 当 URL 仍带 `?localPvp=1` 时，回到主界面不会再次自动拉回 localPvp 对局。
- ViewModel 初始缓存和 HTML 初始 hidden 状态保持一致，避免首屏入口首次同步不显示。

## 状态分层

- `match`：模式、阶段、共享 tick、胜者。
- `world`：星核/食物、黑洞、全局特效和刷新状态。
- `players`：最多 2 个玩家，各自蛇身、方向、速度、得分和存活状态。
- `inputs`：本地、远端、脚本输入统一进入队列。
- `shellView`：主入口、PVP 房间面板、实际对局三个外层视图。

PVP tick 只消费输入命令，不直接依赖 DOM 事件改蛇身。后续接网络时，远端输入应按 `playerId + tick + action + sequence` 放进同一个队列。

## 当前 PVP MVP 玩法规则

当前保留：

- P1/P2 同屏竞技，各自一条蛇。
- 食物/星核拾取、计分和增长共享同一个 `world`。
- 黑洞障碍和黑洞警报共用现有系统。
- 自撞、撞墙、撞黑洞、撞对手身体、蛇头撞蛇头都可结算。
- 头对头同格碰撞会导致双方死亡。
- 同一个星核/食物的同 tick 拾取冲突只结算给一个玩家。
- 最后存活者获胜，同时死亡则为平局。

当前不纳入：

- 星兽。
- 星引仪。
- 排行榜、账号、匹配、观战、聊天、断线重连。
- 真实房间服务和网络同步。

星兽和星引仪先排除，是为了让双蛇移动、碰撞和渲染预算先稳定。等本地双人性能确认后，再逐个实体接入 PVP。

## 后续真实房间 MVP 计划

- 最多 2 人房间。
- 支持创建房间、输入房间号加入、准备。
- 两人都准备后进入 3 秒倒计时，再开始对局。
- 服务端只负责房间状态、准备状态、输入转发和掉线判定。
- 同步策略只同步输入命令和 tick，不同步完整画面。
- 远端输入格式：`playerId + tick + action + kind + sequence`。
- 客户端提前 2-4 tick 做输入缓冲。
- 迟到、重复、乱序输入按 `sequence` 去重。
- 每隔一段 tick 做轻量状态校验；不一致时提示或强制结束本局。
- 首版不做账号、排行榜、聊天、观战、匹配系统。

## 性能护栏

- 继续使用一个 Canvas 和一条 render pipeline。
- 蛇身占用使用数字格子索引：`row * columns + column`。
- 单蛇和双蛇都使用 `Uint8Array` 维护蛇身占用。
- 多人碰撞内部使用 `Int16Array` 做身体占用裁定。
- `GameSnapshot.players` 提供双蛇快照，`renderSnake` 循环绘制。
- 粒子、奖励爆发和拖尾仍然走全局上限，不按玩家数翻倍。
- 房间消息队列未来必须有上限，不能无界累积。
- UI 继续走 ViewModel 差异写入节奏，不按帧硬写 DOM。
- 状态栏 title 包含逻辑耗时和渲染耗时，便于本地压测。
- 性能目标：桌面 PVP 接近 60 FPS，移动端横屏可玩，高压局不能连续卡死。
