# 性能预算

## 总原则

性能优化必须服从玩法冻结原则，不能通过改节奏、改判定、改视觉密度口径来“伪提升”。

## 当前热点

- `Game.ts` 仍保留拾取后的计分、补货、UI/音效等高频编排逻辑
- `renderState.ts` 仍负责粒子、拖尾、震屏、奖励爆散等高频状态更新，后续性能优化应优先看对象复用和数组压缩
- 多处 `cellKey` / `Set<string>` / 数组扫描
- `renderFx.ts`、`renderSnake.ts`、`renderCores.ts` 等绘制模块已经拆出，后续优化要围绕现有 quality level 预算做，而不是继续增加文件数
- 快照与 UI 同步已经进入 `viewModel.ts`，后续重点是减少不必要的派生和 DOM 写入

## 后续优化方向

- 收敛为统一的数值索引与网格工具
- 降低每帧字符串 key 构造
- 复用高频特效对象，优先从 `renderState.ts` 的粒子、拖尾、奖励爆散数组入手
- 缩小需要重建的渲染层范围
- 保持现有 quality level 策略，但让它更清晰可测
- 不通过继续拆一次性 helper 来“伪优化”；性能收益应来自缓存、少分配、少重复扫描和明确的每帧预算
